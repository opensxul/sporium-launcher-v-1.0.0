# Выпуск Sporium для Windows

## Ключ обновлений

Официальный ключ подписи хранится вне репозитория, в `%USERPROFILE%\.sporium-signing\updater.key`. Сделайте защищённую резервную копию ключа: следующие обновления должны быть подписаны тем же ключом. В `tauri.conf.json` находится только публичный ключ. Закрытый ключ, его пароль и файлы авторизации нельзя публиковать или включать в архивы исходников.

Скрипт сборки читает этот путь по умолчанию. Для другой среды задайте `TAURI_SIGNING_PRIVATE_KEY` (путь или значение ключа) и, если нужен, `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`. Для собственного независимого форка создайте свой ключ командой `npx tauri signer generate` и замените публичный ключ, адрес репозитория и адреса обновлений.

Подпись обновления Tauri не является сертификатом Windows Authenticode. Выпуск 1.0.0 не имеет Authenticode-сертификата издателя.

## Сборка

1. Обновите одинаковый номер версии в `package.json`, `package-lock.json`, `src-tauri/Cargo.toml`, `src-tauri/Cargo.lock` и `src-tauri/tauri.conf.json`.
2. Добавьте `docs/releases/<версия>.md` с изменениями.
3. Выполните проверки исходников и `npm.cmd run installer:build`.
4. Проверьте подпись и отклонение повреждённого пакета: `cargo test --manifest-path src-tauri/Cargo.toml --test release_artifact -- --ignored`.
5. Проверьте установку, повторную установку и удаление. Скрипт `scripts/installer-smoke.ps1` использует отдельную папку и проверяет сохранность существующей базы и контрольного файла в каталоге данных. Он не запускает установленный лаунчер и не тестирует миграцию между разными версиями схемы базы.

Артефакты: `SporiumLauncher.exe`, `SporiumLauncher.exe.sig`, `SHA256SUMS.txt`, `latest.json` в `releases/`. Не редактируйте EXE после подписи.

## GitHub Release

Опубликуйте исходники и тег `v<версия>` в `opensxul/sporium-launcher-v-1.0.0`. Создайте обычный, не предварительный Release и прикрепите все четыре артефакта. До публикации держите выпуск черновиком, чтобы лаунчеры не увидели неполный набор файлов. После загрузки файлов опубликуйте его как Latest.

Лаунчер запрашивает `releases/latest/download/latest.json` без авторизации. Репозиторий и файлы релиза должны быть публичными. Если обновления нет или сеть недоступна, окно проверки не появляется. Перед запуском установщика проверяются подпись, подписанный номер версии и отсутствие активной игры/операций с контентом. Модальные окна и блокировки файлов защищают текущую библиотеку.

В первом выпуске можно проверить доступность манифеста и отсутствие предложения установить ту же версию. Полную проверку перехода 1.0.0 → следующая версия нужно выполнить при подготовке следующего выпуска.
