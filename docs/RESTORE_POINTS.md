# Content and project restore points — phase 12

Inside an instance, expand content **History → Restore points**. Select a verified point and confirm restoration. Existing phase-10 pre-update snapshots are supported without migration. The confirmation explains that tracked content added later is removed and that the current tracked set is saved first so restoration can be undone.

Restoration returns exact receipt-owned file bytes, versions, provenance and enabled/disabled state. It works offline, verifies both SHA512 and SHA1 and exact size, and requires the same instance UUID, Minecraft version, loader family and exact configured loader version. Corrupt/missing snapshots and recipe changes disable the point. Modified tracked files, unknown destination collisions and active game/read leases block mutation; manually placed files are never silently adopted, including identical bytes at an untracked destination.

Worlds, screenshots and untracked content are preserved. Tracked world-scoped datapacks can be restored only if their existing world destination is valid. Verified configuration backups can also be restored using **Также восстановить сохранённые настройки / Also restore saved settings**. Older snapshots without configuration hashes remain content-only. The same list includes managed project transactions and their undo points. Required locked configuration follows the restored project manifest; other user settings remain unchanged unless explicitly selected. Recipe/world migration is not part of rollback. See [managed project transactions](MANAGED_PROJECTS.md).

The exclusive instance lease covers preflight, creation of a verified undo point and journal publication. `.sporium/content-restore.json` binds complete before/after receipts to both verified snapshots. Recovery preflights every target before mutation, removes only receipt-owned replaced files, publishes missing verified targets, writes receipts and appends idempotent snapshot/restoration history. Reads and launch recover interrupted restoration before observing the instance. Recovery does not contact Modrinth.

Verification includes unit scenarios for round-trip/undo, modified files, corrupt snapshots, unknown collisions, active leases and interrupted restoration before receipt publication. `npm run test:restore-native` copies only immutable test content from an earlier passed content-update scenario into fresh `.local/content-restore-smoke/data-*`; it never changes the source fixture or normal user library. It exercises the actual embedded executable, cancel/confirmation, both viewport widths, real provider files, undo, restart and corrupt-point refusal.

Managed manifests/policies, Creator Studio, whole-pack checks/repair, configuration restoration and configurable background checks/compatible automatic installation are documented in [MANAGED_PROJECTS.md](MANAGED_PROJECTS.md). See `PROJECT_STATE.md` for current verification evidence.
